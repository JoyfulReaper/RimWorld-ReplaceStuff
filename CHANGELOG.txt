----------------------------------------------------------------
2026-06-19: Performance Edition fork update
----------------------------------------------------------------

This is a fork-level rewrite of Replace Stuff for RimWorld 1.6. The goal is still the original mod's familiar experience: designate a new building over an old one and let the game handle the transition. The major difference is that the internals now use a more explicit replacement pipeline, cached matching rules, and a compatibility handler system so replacements can preserve more state while doing less repeated work.

This changelog focuses on the meaningful differences from the base repo rather than listing every moved file or namespace rename.


Player-facing changes
---------------------

- Reworked the replacement flow around a dedicated replacement frame and pipeline.
  Replacement now has clearer stages for capturing old building state, removing the original, spawning the replacement, restoring data, restoring stored contents, and cleaning up attached structures.

- Improved preservation of building state during replacement.
  The fork can now preserve or restore more data from the old building, including:
  - faction and rotation;
  - quality where applicable;
  - worktable bills;
  - temperature targets for coolers, heaters, and compatible temperature-control buildings;
  - selected plants for growers and hydroponics-style buildings;
  - storage filters, priorities, group labels, and related storage state;
  - compatible wall attachments.

- Improved storage replacement behavior.
  Stored items are extracted before the old storage building is destroyed and restored afterward. Storage group labels and settings are also carried across where possible, including better handling for grouped shelves and nearby companion storage buildings.

- Added safer handling for wall attachments.
  Attachments such as wall lights and related buildings can be captured and restored when the supporting wall is replaced, reducing cases where upgrades silently discard attached objects.

- Expanded over-wall cooler and vent support.
  Over-wall cooler and vent behavior has been reorganized for RimWorld 1.6, with dedicated placement, spawn, construction, and designation-menu patches.

- Improved terrain, rock, fog, and bridge-adjacent placement behavior.
  The old over-mineable and bridge placement code has been reorganized under a broader terrain system. The fork includes more explicit handling for blueprints over mineables, fogged cells, conduit placement, bridge-like terrain, and construction over terrain that needs support.

- Fixed bridge preference settings.
  When more than one bridge-like terrain is available, the settings window can show a preferred bridge order and save that order.

- Flattened/renamed some designation menu behavior.
  The Performance Edition changes include menu cleanup around over-wall cooler entries and the mod settings category now identifies the Performance Edition build.


Compatibility changes
---------------------

- Added a registry-based replacement compatibility system.
  Replacement compatibility can now be described through rules and handlers instead of being hardcoded into one large flow. This should make future mod support easier to add and easier to reason about.

- Added attribute-driven replacement rules.
  Code can register replacement rules with a priority, allowing higher-priority rules to win without tightly coupling all compatibility logic into one class.

- Added attribute-driven replacement handlers.
  Replacement handlers can be discovered automatically and registered against target comp types. Handlers can run before and after replacement to preserve mod-specific state.

- Added XML-backed interchangeable item groups.
  Defs can declare groups of interchangeable buildings/items and optional comp handlers, allowing mod integrations to be added or adjusted with data instead of only C# patches.

- Added a legacy compatibility bridge.
  Existing `IReplacementComp` style integrations can still be adapted into the new handler pipeline, reducing the breakage risk for older compatibility code.

- Added QualityBuilder support.
  QualityBuilder state is preserved through replacement, including skilled-builder designation state and desired quality settings where the external comp is present.

- Added RimFridge support hooks.
  RimFridge building detection and temperature handling are implemented via reflection so the fork can support fridge replacement behavior without requiring a hard dependency.

- Improved support for generic modded temperature controllers and growers.
  State capture now uses common RimWorld interfaces/comps where possible, so compatible modded buildings can benefit without a bespoke patch for every def.

- Reworked and expanded compatibility defs.
  Compatibility defs were moved out of the version-specific `1.6/Defs` folder into shared `Defs`, and many supported integrations were refreshed or restored there, including vanilla/DLC defs and several third-party mod definition sets.


Architecture and performance changes
------------------------------------

- Replaced much of the old scattered replacement logic with a central pipeline.
  Core replacement behavior now lives around `ReplacementPipeline`, `ReplacementFrame`, `ReplacementUtility`, `ReplacementMatcher`, `BuildingStateTransfer`, and `StorageReplacementEngine`.

- Added cached replacement matching.
  `ReplacementMatcher` caches ThingDef-to-ThingDef replacement checks and uses a bounded weak-reference cache for active thing replacement lookups. This reduces repeated scanning in hot placement and construction paths.

- Split feature areas into clearer namespaces and patch groups.
  The old `NewThing`, `OverMineable`, `PlaceBridges`, `DestroyedRestore`, and broad replacement files were reorganized into more focused areas such as:
  - `Core`;
  - `Replace`;
  - `Data`;
  - `Compatibility`;
  - `OverWallCoolers`;
  - `Terrain`;
  - `Terrain/Bridging`;
  - `Utilities`.

- Reworked replacement frame generation.
  Replacement frame defs are generated and registered through a dedicated registrar/generator, with hooks for compatibility systems that need to alter generated frames.

- Added a clearer replacement data model.
  Persistent state is stored in `ReplacementData`, with support for comp handler keys, attached building data, storage data, quality, bills, temperature, grower settings, and arbitrary mod data.

- Reduced broad debug/logging noise in release paths.
  Logging has been consolidated under `RSLog`, with debug-oriented diagnostics gated more cleanly.

- Removed the old tick scheduler.
  The fork no longer depends on the previous `TickScheduler` path.

- Removed several older specialized patch classes after their behavior was folded into the new systems.
  This includes old classes for direct new-thing replacement, destroyed-building revival, bridge placement, over-mineable placement, wall attachment handling, and replacement frames.


Gameplay rule changes and supported replacement categories
---------------------------------------------------------

- Default replacement rules now cover major vanilla categories through centralized rule registration:
  - walls and fences;
  - doors;
  - tables;
  - beds;
  - coolers;
  - vents;
  - growers;
  - batteries;
  - wind turbines;
  - watermill generators;
  - steam geyser buildings;
  - RimWorld 1.6 matching replacement tags;
  - XML-defined interchangeable groups.

- Replacement validation now explicitly avoids replacing a building with an identical non-stuffed building and avoids identical stuff replacements where appropriate.

- Replacement work now shares or adjusts reservations more deliberately so pawns can interact with old buildings and replacement frames without as many construction-order conflicts.

- Replacement construction now increments both construction and deconstruction records for the worker when the replacement completes.


Packaging and project layout
----------------------------

- RimWorld support is centered on 1.6.
  Older version-specific assemblies and legacy 1.1 through 1.5 folders were removed from this fork.

- The old `LoadFolders.xml` layout was removed.
  Shared defs, patches, languages, textures, and metadata now live at the package root or in common folders rather than under only `1.6`.

- Mod metadata was changed for the Performance Edition fork.
  The package ID is now `ReplaceStuff.Performance`, the author is Kyle Givler, and the Steam Workshop ID points at the Performance Edition upload.

- Preview art was replaced and the editable source image was added.

- The solution and project files were updated for the reorganized source tree and current assembly output.

- A project-level MIT license file was added/updated to reflect the original mod foundation and fork ownership.

- README documentation was rewritten for the Performance Edition, including a modder documentation link.


Translations and text
---------------------

- English keyed text was updated for the Performance Edition name, settings, warnings, and menu text.

- Existing language folders were moved out of old version-specific folders and refreshed where needed.

- Over-wall cooler/vent labels and concept text were updated across the available localization files.

- Old HugsLib update news files were removed.


Known risks and testing focus
-----------------------------

This fork changes a large amount of replacement behavior and should be tested like a beta, especially before use in long-running saves.
